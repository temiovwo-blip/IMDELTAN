# Android development and direct-install test plan

Updated 2026-11-06. The customer web scaffold is wrapped in a Capacitor 7 Android project. The temporary development application ID is `com.imdeltan.community.dev`, separate from any existing application; ownership/availability and the eventual release ID need checking. Its display name is IMDELTAN Dev. Android API 23 is the current minimum; target API 35. Internet access is enabled, cleartext HTTP is disabled, and Android backup is disabled for the app.

An automated sandbox build of an 8.1 MB debug APK succeeded and its debug signature was verified. This is only a build check. It has not been installed on a device, is not suitable for testers, has no stable release signature, and must not be used with real accounts or personal data. Debug keys are disposable, not the approved Option B release signing arrangement. A separate debug APK has since been saved for the owner to perform a limited sign-in experiment only; it is not a tester or release artifact.

The live auth service rejects signup; the database and app flows are not connected end-to-end, and the app is far from feature-complete. An APK alone does not make the service ready. Before direct installation by testers: complete core app features, security and moderation controls; use isolated test infrastructure and synthetic/non-sensitive data; finish real API/RLS/auth/MFA/storage and Android device tests; review data handling and deployment; set up a secure dedicated signing key and its backup/custody; and agree on controlled distribution, support and privacy information. No Play Store is needed for an APK sideload; the phone may require permission to install from the chosen source. Provide instructions only when a safe, signed tester build is ready. Public signup remains closed pending legal and security approval.

The `android-debug-build.yml` workflow compiles a non-distributable debug APK with unconfigured web assets; it does not deploy a backend or publish an artifact. Do not put secret keys, signing files or passwords in the repository. `npm run build` and `npx cap sync android` regenerate ignored web assets; set only the appropriate public project URL and publishable key in an environment-specific secure build configuration. Embedded publishable keys are not secrets and rely on correct backend authorization.
